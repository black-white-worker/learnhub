# 2026-10-28

## 修复 start.ps1 启动报错
- 现象：运行 `.\start.ps1 -ForceBuild` 报 `unknown flag: --no-cache`，docker compose 启动失败。
- 根因：`scripts/start.ps1` 把 `--no-cache` 拼进了 `docker compose up -d --build`（第218-219行）。`--no-cache` 只属于 `build` 子命令，不是 `up` 的合法参数。
- 修复：把 `-ForceBuild` 分支拆成两步 —— 先 `docker compose build --no-cache`（重建 backend/frontend），再 `docker compose up -d`。非强制构建仍用 `up -d --build`。已通过 PowerShell 语法解析检查。
- compose 中仅 backend/frontend 有 build 上下文，其余为预置镜像。

## 考试模块：学生端回显老师评语
- 现象：老师批改时填的评语（comment）学生端 /exam/:id 看不到，老师评分能看到。
- 根因：后端 `Detail` 已通过 `mySubmission` 返回 `comment`；`ExamDetailView.vue` 学生端交卷回顾只渲染了 autoScore/teacherScore，模板里没有 comment。
- 修复：新增 `teacherComment` / `resultSummary` 计算属性，在交卷回顾顶部 alert 下方加「老师评语」蓝色卡片；顺带修正 teacherScore=0 时不显示的问题（改用 null 判断）。SFC 编译校验通过。
- 注意：前端改动需重建镜像，`start.ps1` 会因 frontend/src 变化自动重建；若数据库里该提交 comment 本身为空，需要老师重新保存一次批改。

## 修复 start.ps1 -ForceBuild 后端构建过慢
- 现象：改用 `-ForceBuild` 后，每次后端阶段二都重跑 `apk add libreoffice-writer/impress font-noto-cjk`（238 个包，90s+），构建明显变慢。
- 根因：上一轮把 `-ForceBuild` 改成 `docker compose build --no-cache`（整库无缓存）。`--no-cache` 本只为解决前端 WSL2 下 BuildKit 误判 COPY 层导致 dist 不更新；但同样作用于后端，导致与源码无关、内容稳定的 apk 安装层也被强制重装。
- 修复：`start.ps1` 的 `-ForceBuild` 分支改为「`compose build --no-cache frontend`（仅前端无缓存）→ `compose build backend`（后端用层缓存）→ `compose up -d`」。后端 apk 层始终命中缓存，跳过 LibreOffice 重装。PowerShell 语法检查通过。
- 说明：此前"慢"是 my 修改引入的副作用——修复前 `-ForceBuild` 因 unknown flag 根本跑不起来，用户实际走的是 `up -d --build`（有缓存）所以快。
